# AutoShade v1.6.6 — the source tree split into files, nothing else changed

Everything merged into `main` since v1.6.5 ships here, and none of it changes
what the program does. The six source files that had grown past ten thousand
lines each — the develop engine, the sidecar layer, the reverse fit, the zoned
fit, the style library and the develop store — are split into files, and the
three test files of that size are split into parts. Code was moved and not
edited. Every render, recipe, mask raster and sidecar the release code writes
is byte-identical to v1.6.5's — measured on the parity corpus and on the
reference pair, see Gates — and every test keeps its name and its path. The
desktop app, the command line, the sidecar layer and the weights are v1.6.5's
in behaviour; a user of v1.6.5 sees nothing new on screen.

The split tooling, the proofs and this document are the maintainer's; no
external coding model wrote this release.

## The source tree

- **What was split, and how.** Each module stays the module: `render.rs`,
  `xmp.rs`, `fit.rs`, `fit_zoned.rs`, `style.rs` and `store.rs` are now roots
  of 124 to 378 lines — the module doc, the imports, the `mod` declarations
  and a re-export of every moved item in the visibility it had — so no path
  into the library changed, and the moved code sits in files under a directory
  of the module's name. Each module's own tests moved to `tests.rs` under that
  directory as the same `mod tests`, so every test keeps its path
  (`render::tests::…`, `xmp::tests::…` and so on). The engine went from 21,842
  lines to 18 files plus its tests; the sidecar layer from 19,726 to 13 files;
  the reverse fit from 16,910 to 16; the zoned fit from 11,388 to 10; the
  style library from 10,782 to 11; the store from 10,248 to 13. The largest
  file in the tree is now `pipeline.rs` at 8,558 lines.
- **Moved, not edited, and accounted for.** Every split was generated by one
  script from the committed file, and its accounting proves that every
  non-blank line of the old file lands exactly once in the new ones — nothing
  missing, nothing duplicated — beyond the scaffolding the layout needs (a doc
  line and an import per file, the `mod` and re-export lines). The whole crate
  grew from 227,606 lines to 228,784 through the splits — 1,178 lines of
  scaffolding (three more lines came with the test correction named under
  Gates). The only edits to moved text are visibility: a private item that
  another file of its module now names became `pub(super)` — 111 in the
  engine, 103 in the sidecar layer, 141 in the reverse fit, 72 in the zoned
  fit, 70 in the style library, 73 in the store plus 11 private fields and
  methods — and 171 of those names are re-exported only for test builds,
  because only test code reaches them. Each promotion was named by the
  compiler and resolved by a script against the original file, so the plan of
  every split is the whole record of what was touched.
- **The three test files past ten thousand lines** — the desktop app's (11,713
  lines), the engine's (11,476) and the sidecar layer's (10,354) — each became
  a short stub (21, 19 and 17 lines) that keeps the file's own header and
  imports and splices the tests back in with `include!` from parts under
  `tests/` (13, 13 and 11 files of 377 to 1,666 lines). An included file's
  items are items of the module that includes it, so nothing changed
  visibility and every test keeps its name and its path. The parts are
  verbatim; the three edits the layout forced are counted: 33 `include_str!`
  paths gain one `../` because such a path is relative to the file that holds
  it, the desktop app's control census skips the parts under `tests/` the way
  it skipped its own file, and the two source-text constants that read a whole
  test file now read the parts and the stub in include order — the same text.
- **The tests that read the source read the split source.** A dozen library
  tests scan a module's own text for a property — that the mosaic denoise runs
  before demosaic, that the hot-pixel mapping precedes every reader of the
  mosaic, that every store read goes through the capped reader, that the
  engine never calls the analyzer. Each split module now exposes its files as
  one text, root last, and those tests read that; a mutation that hands them
  the root alone turns every one of them red, so they still see the code they
  pin.

## Documents and the site

- **ARCHITECTURE** gains, for each split module, the paragraph that names what
  each file under its directory holds, and its pointers into the tree follow
  the code (the sidecar reader, the raster-ownership claim, the 33-phrase
  vocabulary and the style index now name the files they live in).
  **TECH_STACK**'s pointers follow the same way; its sentences that name a
  module by its root file still hold, since the root is the module. **README**
  is unchanged but for its version words. The site changes only its version
  words, its battery line and its cache keys.

## Compatibility

No recipe, sidecar, store or weight format changes, and no change to any
pixel: the release CLI's renders on the parity corpus and on the reference
pair are the bytes v1.6.5's CLI wrote (Gates). The sidecar weights stay pinned
to the v1.6.0 `autoshade-raw-denoise-v2.pth`; no weights are re-shipped. For
anyone building from source: every `use` path into the library is unchanged;
only the file a definition lives in moved.
